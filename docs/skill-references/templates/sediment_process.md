# 沉淀流程（默认模板）

业务 skill 在 `project.yaml` 里把 `mounts.sediment_process` 指到本文件或自己的副本。仅当 `sediment: on` 时，收尾打开本文件并执行。`sediment: off` 跳过三问与入池（审查仍可在报告里写观察）。

`gate_on` 只决定何时必跑门禁，不决定是否沉淀。

## 收尾自问

1. 是否出现**新的可晋升单元**（规范 / 范式 / 定级桶，以该 skill 的 `version_counts` 为准）？
2. 是否出现**新反例**（能追到 changelog 或审查报告）？
3. 是否与现有规则**冲突**？

三句全「否」：不改 skill 结构，回报里仍写三问和短理由。

有「是」时：

- **小结级**（补反例、改措辞）：当场写入 `mounts.anti_patterns`（若已挂载）；不升版本文件。
- **规范级**（新增可晋升单元、改 description、改计数清单、改门禁脚本）：只追加 `mounts.backlog` 的「## 候选」。用户批准后再改正式文件，从候选段删除并追加「## 已晋升」，同时升版本。

## 准入三条件

写入正式文件前三条都要满足：跨需求可复用；有真实事故佐证；已经验证过（审查闭环或真机）。

## 不收四类

| 类型 | 去处 |
|---|---|
| 个案取值 | 业务 changelog |
| 还没定的欠账 | `mounts.backlog` |
| 临时绕法 | changelog |
| 没有佐证的经验 | 不写 |

## 池

- 只写本 skill 的 `mounts.backlog`。禁止自动写入别的 skill 的池。`peer_pools` 只提示人工抄录。
- 未批准的候选不能当正式规则用。池里还有条目时，收尾写出「待你批：N」。
