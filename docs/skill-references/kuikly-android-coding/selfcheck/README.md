# 规范自检清单（码农收尾用）

> **用途**：把「规范自检」从"凭记忆挑条款"变成"照清单逐行打勾"，堵住「只写做对的、漏掉没做的」。
> **配套**：`.cursor/skills/kuikly-android-coding/SKILL.md` §规范自检 / §实现回报模板。
> **不替代规范全文**：清单只提供"该检查哪些条款"，判据细节仍以 `norms[].ref` 全文为准。

## 一、三态（只许这三种，**禁止缺行、禁止留空**）

| 记号 | 含义 | 必填内容 |
|---|---|---|
| `OK` | 条款命中且已做到 | **落点行号**（`文件:行`），不接受"已遵守"这种空话 |
| `TODO` | 条款命中但本轮没做 | **为什么不做 + 谁承担风险**（例：与 L3 冲突 / 另立任务 / 用户裁定不做） |
| `N/A` | 条款与本轮改动面无关 | **一句判据**（例：本轮无新建文件 / 无覆盖方法） |

## 二、怎么用

1. **按改动面选清单**：动 `.java` → `selfcheck/lang_java.md`；动 `.kt` → `lang_kotlin.md`；**任何业务改动**都加 `platform_android.md`；触及 Compose UI / 手势 / 页面 → 加 `platform_kuikly_compose.md`；改库公开 API / Stage / Session / Processor / Painter → 加 `perspective_crop_api.md`；新建文件再加 L3（清单文件名 = norm id）。
   > 混淆（`project/proguard_when_enabled.md`）为**休眠条款**：本仓 `minifyEnabled=false`，不在 `norms[]`、无对应清单；仅当本单开启 release 混淆时才按该文件执行。
2. **逐行填三态**，行数不许少：清单有 N 行，回报里就得有 N 行（可合并同一条款的多处落点，但不许整行缺失）。
3. **`TODO` 行会被审核员单独看**：审核员按此判「未做是否有正当理由」，无理由的 `TODO` 直接开 P1。

## 三、为什么需要它（历史事故）

2026-10-27「AR 预览复制落点」一单：自检栏只写了做到的条款（空指针判空、私有化、命名），漏了 `lang_java`「能 final 尽量 final」，也没写"为什么不做"。结果是**检查表变成自我证明，漏项不暴露**。此清单就是那次事故的制度化补丁。

## 四、维护规则

- `project.yaml` 的 `norms[]` 增删规范 → 本目录同步增删对应清单文件（一份规范一个文件，文件名 `{norm_id}.md`）。
- 规范全文（`norms[].ref`）改了条款 → 同步改清单行；清单只摘条款名 + 判据，**不复制正文**，避免双源漂移。
- 清单条数变化不影响代数（代数 == `norms.length`，与本目录无关）。
